# MCU-slave-device 逐模块迁移记录

## 最高优先级：等价移植约束

本项目只进行硬件平台移植，不进行功能重写、算法优化或参数调整。

以下内容必须与原工程保持一致：

- 通信协议、帧格式、命令字、CAN ID 和波特率。
- 数据类型、变量含义、单位、正负方向和取值范围。
- PWM 数值、控制周期、延时时间和状态机切换条件。
- 麦克纳姆轮计算公式、PID 参数、传感器换算公式。
- 电机、舵机、水泵及其他执行器的原有动作逻辑。

只允许为适配新开发板修改：

- GPIO 引脚映射。
- 定时器、UART、CAN、I2C 等外设实例和复用配置。
- 时钟使能、中断入口和底层初始化代码。
- Keil 工程分组、头文件路径和必要的硬件适配层。

如果引脚冲突或外设资源不足导致无法保持原行为，必须先停止迁移并确认方案，不通过修改业务数据或算法规避问题。

## 迁移原则

- `E:\project_M\src` 只读，不在原工程中修改代码。
- 新代码只放入 `E:\project_M\test_p`。
- 不复制原工程的构建产物和无关自动生成杂项；原工程实际参与运行的业务模块必须完整迁移。
- 每次只增加一个可独立验证的功能。
- 每个阶段依次完成：编译、接线检查、上电测试、结果记录。
- 单模块未通过时，不进入状态机和整机联调。

## 源文件注释规范

所有新增或迁移的 `.c`、`.h` 文件，必须在文件第一行开始写明：

1. 文件名称。
2. 对应引脚资源。
3. 使用的 STM32 外设资源。
4. 模块功能。
5. 模块在整机中的用途。
6. 原工程来源文件。
7. 移植中允许发生的硬件适配。

统一文件头模板：

```c
/**
 ******************************************************************************
 * @file    ModuleName.c
 * @brief   模块功能的简短说明
 *
 * @pin_resources
 *   - PAx : 信号名称、输入/输出方向、复用功能
 *   - PBy : 信号名称、输入/输出方向、复用功能
 *   - 无直接 GPIO 的算法文件必须明确写：无直接 GPIO，由底层模块提供数据。
 *
 * @peripherals
 *   - USARTx / TIMx_CHx / CAN1 / I2C1 等实际使用的片上外设
 *
 * @function
 *   - 本文件提供的功能，不描述未实现的能力
 *
 * @purpose
 *   - 本模块在整车中的实际用途
 *
 * @migration
 *   - 原文件：E:\project_M\src\...
 *   - 保持不变：协议、参数、公式、数据类型和业务行为
 *   - 允许修改：引脚、外设实例、初始化和中断映射
 ******************************************************************************
 */
```

头文件和源文件都要有文件头。函数内部仍需保留与原工程一致的关键数据含义、单位、方向和范围说明。

## 目标工程结构

```text
test_p
├─ Start/               STM32F103C8T6 启动与 CMSIS
├─ Library/             STM32F10x 标准外设库
├─ System/              系统时基与基础服务
├─ User/                main、中断和工程配置
├─ Hardware/            UART、电机、CAN、舵机、传感器等硬件驱动
├─ Algorithm/           原工程已经使用的运动学与控制算法
└─ App/                 原工程上位机协议和状态机
```

只有实际需要时才创建 `Algorithm` 和 `App`，不提前生成空文件或重复目录。

## 已确认的 USART2 TTL 基线

```text
USB-TTL TXD -> PA3 / USART2_RX
USB-TTL RXD <- PA2 / USART2_TX
USB-TTL GND -> 开发板 GND
PA6 = 0      -> 关闭板载 RS485-2 发送器
PA7 = 1      -> 关闭板载 RS485-2 接收输出
```

对应代码：

- `Hardware/UART.c`
- `Hardware/UART.h`
- `User/main.c`

## 建议迁移顺序

### 阶段 2：冻结引脚

先生成唯一的引脚分配表，禁止后续模块临时占用已分配引脚。当前必须保留：

- PA2/PA3：USART2 TTL 上位机通信。
- PA6/PA7：板载 RS485-2 禁用控制，不能继续作为原工程舵机 PWM。
- PB8/PB9：板载 CAN1。
- PA13/PA14：SWD 下载调试。

原工程 TIM2 的 PA2/PA3 电机 PWM 因 USART2 冲突，必须迁移到其他定时器通道。

当前候选资源表如下。除已经实机通过的 USART2 外，其余项目必须经过原理图、芯片复用表和编译测试后才能标记为“已冻结”。

| 功能 | 候选引脚 | 外设资源 | 当前状态 |
|---|---|---|---|
| 上位机发送 | PA2 | USART2_TX | 已实机通过 |
| 上位机接收 | PA3 | USART2_RX | 已实机通过 |
| 关闭 RS485-2 发送 | PA6=0 | GPIO 输出 | 已实机通过 |
| 关闭 RS485-2 接收输出 | PA7=1 | GPIO 输出 | 已实机通过 |
| SWDIO | PA13 | SWD | 必须保留 |
| SWCLK | PA14 | SWD | 必须保留 |
| CAN_RX | PB8 | CAN1 重映射 | 待单模块测试 |
| CAN_TX | PB9 | CAN1 重映射 | 待单模块测试 |
| I2C1_SCL | PB6 | I2C1 | 待单模块测试 |
| I2C1_SDA | PB7 | I2C1 | 待单模块测试 |
| 左前电机 PWM | PA0 | TIM2_CH1 | 候选，未冻结 |
| 左后电机 PWM | PA1 | TIM2_CH2 | 候选，未冻结 |
| 右前电机 PWM | PA8 | TIM1_CH1 | 候选，未冻结 |
| 右后电机 PWM | PA11 | TIM1_CH4 | 候选，未冻结 |

电机方向 GPIO、D24A STBY 和后续执行器引脚必须在检查全部原工程资源后统一确定，不能边写代码边临时分配。

### 阶段 3：四路电机

1. 只初始化四路 PWM 和方向 GPIO，默认 PWM=0。
2. 只连接左前电机，测试停止、低占空比正转、低占空比反转。
3. 按相同步骤依次测试左后、右前、右后。
4. 四路分别通过后，再测试前进、后退、横移和原地旋转。
5. 此阶段只做开环 PWM，不加入编码器、PID、状态机和上位机运动协议。

验收时保持原工程的 PWM 周期、速度数据、正负方向定义和四轮通道含义，不通过改变速度值掩盖接线或方向错误。

### 阶段 4：CAN

1. CAN1 使用 PB8/PB9 重映射。
2. 先做内部回环测试。
3. 再连接板载 CAN 收发器和真实 CAN 总线。
4. 检查波特率、终端电阻、发送、接收和总线断开恢复。

### 阶段 5：其他硬件

每个模块建立单独的最小测试入口，建议顺序：

1. 舵机
2. 超声波
3. 水泵
4. 姿态传感器
5. 其余 CAN 执行器和监测模块

### 阶段 6：上位机协议

UART 底层保持不变，原样迁移原工程协议解析模块。帧格式、命令字、数据长度、校验方式、波特率和应答内容不得修改。先验证原有普通指令和错误输入处理，再连接电机等真实执行器。

### 阶段 7～8：控制与整合

最后迁移原工程的航向 PID 和状态机，保持原参数、公式和调用顺序。是否迁移某个文件以原 Keil 工程的实际编译成员和运行调用链为准；不擅自启用原工程未参与运行的代码，也不删除原工程已经启用的功能。
